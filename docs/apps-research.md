## Обзор рассмотренных решений

Все три инструмента решают одну задачу — забирать сообщения, участников и метаданные из Telegram-группы через MTProto (тот же протокол, что использует официальное приложение) и складывать это в базу данных, а не через ограниченный Bot API. Все три построены на Telethon (Python-библиотека для MTProto), поэтому логика авторизации и структура доступа к данным у них однотипна: нужны свои `api_id`/`api_hash` с my.telegram.org и вход по номеру телефона от обычного пользовательского аккаунта.[^1][^2][^3]

| Параметр | telegram-export | tg-archive | telegram_exporter |
|---|---|---|---|
| БД | SQLite | SQLite (`data.sqlite`) | SQLite (`db.sqlite3`) |
| Дополнительный экспорт | Нет (только БД + просмотр) | Статический HTML-сайт, RSS/Atom | Авто-CSV и JSON после каждого запуска[^2] |
| Профили пользователей | Да — user bios, avatars, история имён во времени[^1] | Да — локально скачивает аватарки[^3] | Частично — метаданные сообщений, авторство, без явного дампа био |
| Docker / CI-CD | Нет | Нет (просто `uv pip install`)[^3] | Есть, готовый образ на Docker Hub, CI/CD на GitHub Actions[^2] |
| Активность поддержки | Пре-1.0, обновляется медленно, схема БД может меняться[^1] | Автор прекратил активную поддержку, но принимает PR (1.1k stars, релиз май 2025)[^3] | Маленький проект (1 star), последний релиз декабрь 2024[^2] |
| Формат запуска | CLI-команда `telegram-export`, whitelist чатов через config.ini[^1] | CLI: `--new`, `--sync`, `--build`, легко ставить на cron[^3] | CLI с флагом `--chat`, плюс докер-контейнер с volume для данных[^2] |

## telegram-export

Это исторически первый специализированный инструмент именно под задачу "скачать пользователей, чаты, сообщения и медиа в базу". Он явно ориентирован на полноту профилей: сохраняет био пользователей, фото профиля, описания каналов и даже историю изменения имени пользователя во времени, чего нет у большинства аналогов. Настройка идёт через `config.ini` с whitelist/blacklist чатов, а список нужных ID диалогов получается через встроенную команду `--list-dialogs`.[^1]

Минусы: проект давно находится в статусе "пре-1.0" и в документации прямо сказано, что схема базы может меняться без обратной совместимости, то есть при обновлении возможна потеря совместимости со старыми дампами. Разработчики отдельно подчёркивают, что инструмент использует ту же технологию, что и юзерботы, но сам по себе не выполняет активных действий, поэтому не должен приводить к блокировке аккаунта.[^1]

## tg-archive

Наиболее зрелый и популярный из трёх (1.1k звёзд на GitHub, 163 форка, 27 релизов, последний — май 2025), хотя автор официально заявил о прекращении активной разработки, лишь рассматривая пул-реквесты. Работает по циклу `--new` → `--sync` → `--build`: первый вызов создаёт конфиг, `--sync` докачивает только новые сообщения в SQLite с момента последней синхронизации (что удобно для длительного, а не разового мониторинга), `--build` рендерит статический сайт-архив наподобие почтовой рассылки.[^3]

Из практических плюсов для сбора профилей — инструмент локально скачивает аватарки участников, поддерживает отображение результатов опросов и рендер медиа непосредственно в архиве. Sync можно прерывать (Ctrl+C) и продолжать позже, а весь процесс легко автоматизировать через cron-задание для непрерывного накопления данных. Явное предупреждение из документации: при скачивании большого объёма истории и медиа из крупных групп можно упереться в лимиты Telegram API (rate limits), это стоит учитывать при первом полном сборе.[^3]

## telegram_exporter

Самый "production-ready" по упаковке: готовый Docker-образ на Docker Hub, настроенный CI/CD на GitHub Actions (линтинг flake8, юнит-тесты, автосборка и публикация образа), запуск одной командой `docker run` с монтированием volume для данных. После каждого запуска автоматически обновляются три файла — `db.sqlite3`, `html.csv` и `html.json`, что удобно, если дальше данные нужно сразу забирать во внешние инструменты анализа (Excel, Python-скрипты, сторонние системы) без дополнительной обвязки.[^2]

Особенность — инструмент умеет автоматически извлекать все URL из сообщений (включая ссылки, скрытые под текстом) и сохранять их в отдельную колонку `urls` в базе, что полезно для последующей аналитики контента чата. Минус — проект совсем небольшой (1 звезда на GitHub, последний релиз декабрь 2024), то есть community-поддержка и проверка в бою значительно слабее, чем у tg-archive.[^2]

## Как выбрать между тремя вариантами

- **Нужна максимальная полнота профилей пользователей** (био, история имён, аватары, описания каналов) — предпочтителен telegram-export, изначально спроектированный именно под это.[^1]
- **Нужна стабильная, проверенная сообществом схема непрерывной синхронизации сообщений** с возможностью работы через cron и отдельным хранением аватарок — предпочтителен tg-archive за счёт зрелости и большого числа релизов/форков.[^3]
- **Нужен готовый Docker-контейнер с CI/CD и автоматической выгрузкой в CSV/JSON для передачи в другие системы** — предпочтителен telegram_exporter, несмотря на меньшую популярность, за счёт наиболее "упакованного" деплоя.[^2]

Во всех трёх случаях итоговое хранилище — SQLite, поэтому дальнейшая интеграция с внешней СУБД (PostgreSQL, ClickHouse и т.п.) требует одного дополнительного шага — миграции/синхронизации данных из SQLite, что не является архитектурной проблемой, поскольку схемы таблиц (users, messages, media) у всех инструментов простые и однотипные.[^2][^3][^1]
